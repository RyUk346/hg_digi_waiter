# Hyperglow Tabletop

Customer-facing tabletop ordering app for **Hyperglow Café**.
React Native 0.76 · NativeWind v4 · React Navigation · Zustand.

Target hardware: **Rockchip rk3568 / rk3566** Android 11 tablet, 800×1280 portrait, 4 GB RAM, 32 GB storage.
The UI is responsive and adapts to other Android tablets (600–1280 width tested).

## First-time setup

> The `android/` folder is **not** committed — it's auto-generated by the
> React Native CLI. Run the steps below once to scaffold it, then copy your
> Hyperglow source files into the result.

### 1. Scaffold the native project (one time)

From a **scratch directory** (not inside this repo):

```powershell
# Windows PowerShell
npx @react-native-community/cli@latest init HyperglowTabletop `
  --version 0.76.5 --skip-install --pm npm
```

This creates `HyperglowTabletop/android` and `HyperglowTabletop/ios`.

### 2. Merge with this project

Copy the generated `android/` folder (and `ios/` if you ever want iOS) into
this repo's root, **next to** `App.jsx`:

```powershell
# Copy from the scaffold into tabletop-app/
Copy-Item -Recurse <scratch>/HyperglowTabletop/android  <this-repo>/
Copy-Item -Recurse <scratch>/HyperglowTabletop/ios      <this-repo>/   # optional
Copy-Item        <scratch>/HyperglowTabletop/.gitignore <this-repo>/   # only if you don't already have one
```

Delete the scaffold directory afterwards.

### 3. Install JS dependencies

```powershell
npm install
```

This pulls in NativeWind, Reanimated, React Navigation, Zustand, etc.
(All deps are pinned in `package.json`.)

### 4. Configure Android for Android 11 minimum

Open `android/build.gradle` and set:

```gradle
buildscript {
    ext {
        buildToolsVersion = "35.0.0"
        minSdkVersion = 30           // ← Android 11
        compileSdkVersion = 35
        targetSdkVersion = 35
        ndkVersion = "26.1.10909125"
        kotlinVersion = "1.9.24"
    }
}
```

Open `android/app/build.gradle` and verify:

```gradle
android {
    defaultConfig {
        applicationId "com.hyperglow.tabletop"
        // …
    }
}
```

### 5. Wire Reanimated (required for navigation animations)

Already configured for you in `babel.config.js`. The Reanimated plugin
**must be the last** entry in the `plugins` array — don't reorder.

### 6. Optional: install lucide-react-native icon fonts

`lucide-react-native` ships pure SVG icons via `react-native-svg`, so no
extra linking is needed.

## Running it

### On the rk3568 tablet over ADB

1. Enable **Developer options** on the tablet (Settings → About → tap build number 7×).
2. Enable **USB debugging** and connect via USB-C.
3. Confirm the device shows up:
   ```powershell
   adb devices
   ```
4. Start Metro and build:
   ```powershell
   npm start          # in one terminal
   npm run android    # in another
   ```

### On an emulator

Create a Pixel C / Nexus 9 sized AVD running **Android 11 (API 30)** at
800×1280 resolution and run `npm run android`.

### Release build

```powershell
npm run android:release
# APK lands at android/app/build/outputs/apk/release/
```

You'll want to sign + zipalign this for the production fleet — see the
[React Native signing guide](https://reactnative.dev/docs/signed-apk-android).

## App flow

```
Welcome ──tap──▶  Home
  ▲                │
  │            tap category
  │                ▼
  │             Category ──tap item──▶ ItemDetail
  │                                       │
  │                                  add to cart
  │                                       ▼
  │                                     Cart  ──checkout──▶  Payment
  │                                                              │
  │                                                       NFC tap simulated
  │                                                              ▼
  └──── end session ──────────────  OrderStatus  ◀───────  OrderConfirmed
```

Cart + active order live in **Zustand** (`src/store/`) and survive
in-app navigation. They reset only on `clearCart()` / `closeOrder()`.

**Dev tip:** on the OrderStatus screen, *tap the big status headline* to
cycle through Accepted → Preparing → Ready. This is a temporary hook for
testing the live UI before the websocket backend lands.

## Responsive layout

`src/hooks/useResponsive.js` returns a layout token from
`useWindowDimensions`. Used by `HomeScreen` to switch grid columns.
For finer tuning, NativeWind responsive prefixes are available:

```jsx
<View className="px-4 md:px-6 lg:px-10">…</View>
```

Breakpoints (configurable in `tailwind.config.js`):
- `sm` ≥ 640
- `md` ≥ 768  (default tablet — applies on the rk3568 in portrait)
- `lg` ≥ 1024 (landscape / kitchen-style screens)
- `xl` ≥ 1280

## Style system

All colors live in `tailwind.config.js` **and** `src/constants/colors.js`
(mirrored so non-Tailwind contexts — SVG fills, StatusBar `barStyle`,
gradient stops — can read them). Update both when adjusting the palette.

Key Tailwind utilities used throughout the app:

| Class           | What it is                                  |
|-----------------|---------------------------------------------|
| `bg-brand`      | `#F26B3A` (primary)                         |
| `bg-brand-light`| `#FEE6DC` (washes, tinted backgrounds)      |
| `bg-surface`    | `#FAFAF7` (page bg)                         |
| `bg-card`       | `#FFFFFF` (cards, top bars)                 |
| `text-ink-900`  | `#1A1A17` (primary text)                    |
| `text-ink-500`  | `#8A887E` (muted)                           |
| `border-line`   | `#E5E3DA` (card borders)                    |
| `status-*`      | accepted / preparing / ready / out          |
| `tint-*`        | matched soft-fill backgrounds for status    |
